**版本：** V1.0（开发交付版）  
**编制日期：** 2026-10-29  
**项目仓库：** https://github.com/kingiswenwen/kidbridge  
**目标平台：** H5（首要验收）；微信小程序（兼容性验收）  
**文档状态：** 需求与架构基线已形成；高保真 UI、美术资源待设计确认；**尚未修改项目代码**。

> **开发阅读指引：** 第 1–5 章说明做什么和怎么交互；第 6–9 章说明如何实现；第 10–12 章用于拆分开发、测试和验收。本文将“已确定需求”和“建议默认值”区分表述。若无进一步产品反馈，开发可按建议默认值实施。

## 1. 项目背景与目标

### 1.1 背景与现状

KidBridge（彩虹桥）目前是面向亲子学习的 Web/uni-app 项目，已有资源导航、数学练习、拼音学习、英语启蒙、数学闯关、学习记录及设置等功能。现有首页 `src/pages/home/index.vue` 已有“今日学习”卡片，当前 `src/pages/math/challenge/index.vue` 已有闯关星级；但**没有日常生活任务、儿童自主打卡、家长审核、可消费成长积分和奖励兑换的完整业务闭环**。

仓库目前采用 **uni-app + Vue 3 + TypeScript + Pinia + uview-plus + Tailwind CSS + Vite**。应用数据主要通过 `uni.getStorageSync` / `uni.setStorageSync` 持久化，本期不假设已有云端账号或同步服务。当前 `src/pages.json` 配置了五个底部 tab：首页、数学、拼音、英语、闯关。

### 1.2 产品目标

将现实生活中的待办任务转化为孩子愿意主动参与的轻量赛车冒险：**家长安排任务 → 儿童查看并执行 → 进行打卡 → 审核（可选）→ 赛车前进和星星入账 → 兑换装扮或亲子奖励**。

目标体验：

1. **家长设置简单：** 模板复用和周期任务，设置一次可每天自动出现。
2. **儿童操作低门槛：** 适合 3–6 岁，特别是约 4 岁孩子；以大图标、短文案、语音反馈为主。
3. **现实行动优先：** 完成任务才产生进度，互动反馈短促，不诱导长时间游戏。
4. **家长掌控规则：** 审核开关、奖励内容、星星数及日程由家长管理。
5. **工程可扩展：** 首发本地持久化，保留后续接入云同步、多孩子和学习自动打卡的演进空间。

### 1.3 核心设计原则

- **一个自然日 = 一条今日赛道**；每个有效任务对应一个站点。
- 儿童**可以自由决定任务完成顺序**；进度按已确认完成的任务数推进，而非强制依次闯关。
- 未完成、跳过、休息不视为失败；不扣除已经获得的成长星星。
- “学习关卡星级”与“可消费成长星星”是**两套不同的数值**，绝不混算。
- 任务提交不代表完成；家长审核型任务须经批准后才发星星及触发赛车前进。
- 奖励与任务数据必须防止重复确认、重复发分和重复扣分。

## 2. 范围、角色与版本界限

### 2.1 用户角色

| 角色 | 能做什么 | 限制 |
|---|---|---|
| 儿童 | 查看今日任务、查看详情、提交打卡、查看赛车及奖励、兑换数字装扮、申请现实奖励 | 不能创建/删除任务、修改分值、审核自身任务或删除数据 |
| 家长 | 创建/修改/停用任务、审核、设置奖励、确认兑换及兑现、查看记录、配置儿童模式 | 通过家长入口进入；本地 PIN/成人验证仅防误触，不是强安全认证 |
| 系统 | 按周期生成每日任务、计算赛道进度、执行幂等积分操作、持久化 | 自动确认只对明确允许的自助型任务/受信任学习事件生效 |

### 2.2 首发版本（MVP）必须具备

- 今日赛道首页及全部当日任务列表；日程按早晨、下午、晚上、随时分类。
- 任务详情（大图标、简要步骤、语音播报入口）、儿童打卡与待审核状态。
- 家长任务模板、新建/编辑/停用、重复周期、当天任务管理与审核。
- 赛道进度、任务完成即时反馈、冲线庆祝及音效开关。
- 成长星星流水、奖励仓库、基础数字装扮兑换、车库换装。
- 现实奖励申请、家长批准、待兑现/已兑现及取消退款记录。
- 本地持久化与数据恢复后状态正确；首页入口、个人中心家长入口。
- H5 移动端/桌面端响应式；微信小程序构建与关键页面手动验证。

### 2.3 非本期（后续迭代）

- 家长手机与儿童平板跨设备实时同步、多孩子档案、家长远程推送。
- 拍照打卡、AI 图像审核、定位验证、云端推送。
- 完整 3D 赛车、多人竞速、排行榜、商城支付、广告。
- 数学/英语/拼音模块的自动学习打卡（预留事件接口，后续启用）。
- 复杂连续签到惩罚、掉星惩罚、错过任务弹窗催促。

### 2.4 建议默认值（可由家长调整）

| 项目 | 建议默认值 |
|---|---|
| 每日任务数 | 首次引导推荐 3–5 项，系统技术上支持 1–12 项 |
| 任务分值 | 默认 2 星，允许 0–3 星；0 星任务也能推进赛道 |
| 审核方式 | 现实生活任务默认家长审核；另可选择孩子自助确认 |
| 重复周期 | 每天 / 选定星期 / 单次日期 |
| 默认展示 | 首页「今日赛道」入口，不新增第六个底部 Tab |
| 动画时长 | 常规 2–3 秒，允许跳过；适配系统减少动态效果 |
| 奖励余额 | 仅从成长星星流水计算，严禁负余额消费 |
| 数据保存 | 首发同设备、本地存储；本地清理后无法保证恢复 |

## 3. 信息架构与导航

```text
KidBridge 互动学习首页
  └─ 今日赛道（儿童主页面）
      ├─ 任务详情 → 打卡 → 等待审核 / 已完成反馈
      ├─ 赛车前进动画（覆盖层，非路由）
      ├─ 奖励仓库
      │   ├─ 赛车装扮 → 兑换 → 我的车库
      │   ├─ 现实奖励 → 申请兑换
      │   └─ 我的奖杯（只读）
      └─ 我的赛车（车漆、贴纸、轮毂预览与换装）

个人中心（我的）
  └─ 家长入口（验证）
      ├─ 今日审核
      ├─ 任务管理 → 新建/编辑 → 模板与周期设置
      ├─ 奖励管理 → 新建/编辑奖励、兑现记录
      └─ 成长记录 / 配置
```

- `src/pages.json` 注册新页面；不调整现有底部五个 Tab 的结构。
- H5/小程序页面之间使用项目现有 `uni.navigateTo` 约定；首页 Tab 仍使用 `uni.switchTab`。
- 返回逻辑：任务详情完成后返回「今日赛道」；奖励兑换后保留当前奖励仓库位置；从任意子页面可返回父页面。

## 4. 页面线框规格与交互状态

### S01 — 今日赛道（儿童）

**目的：** 进入后 3 秒内知道今天有几个任务、完成了多少、还能做什么。

```text
┌───────────────────────────────────────┐
│ ← 今日赛道                  ⭐ 18      │
│ 早上好，小赛车手！                     │
│      🏎️      今天完成 2 / 5 站         │
│ 起点 ━━━●━━●━━○━━○━━○━━ 🏁 终点        │
│                                       │
│ 今天还有 3 个挑战                      │
│ ┌───────────────────────────────────┐ │
│ │ 🪥 早上刷牙           ✅ 已完成    │ │
│ └───────────────────────────────────┘ │
│ ┌───────────────────────────────────┐ │
│ │ 🧸 整理玩具           ✅ 已完成    │ │
│ └───────────────────────────────────┘ │
│ ┌───────────────────────────────────┐ │
│ │ 📖 阅读绘本             去完成 ›  │ │
│ └───────────────────────────────────┘ │
│ ┌───────────────────────────────────┐ │
│ │ 🏃 户外运动             去完成 ›  │ │
│ └───────────────────────────────────┘ │
│ ┌───────────────────────────────────┐ │
│ │ 🔢 数学小游戏           去完成 ›  │ │
│ └───────────────────────────────────┘ │
│     [🏎️ 我的赛车]   [🎁 奖励仓库]       │
└───────────────────────────────────────┘
```

**内容与动作：** 顶部昵称/今日进度/成长星星；一条可缩放或抽象化的赛道；按时段组织的完整任务列表；一眼能区分待完成、待确认、已完成、跳过；赛车与奖励两个入口。已完成任务可回看，不再显示打卡按钮。

**空态：** 当日 0 项任务显示“今天是自由冒险日”，不生成空冲线奖励；提供家长设置入口（需验证）。**长任务列表：** 超过 8 项则采用固定顶部进度 + 下方滚动任务列表；所有站点信息仍然可达。

### S02 — 任务详情与打卡（儿童）

```text
┌───────────────────────────────────────┐
│ ← 挑战任务                             │
│                 🧸                     │
│              整理玩具                  │
│     把小汽车和积木送回家！              │
│          [🔊 听一听]                   │
│                                       │
│  ○ 把小汽车放回车库                    │
│  ○ 把积木放回盒子                      │
│  ○ 检查一下地面                        │
│                                       │
│        完成奖励：⭐ +2                 │
│                                       │
│          [ 我完成啦！ ]                │
└───────────────────────────────────────┘
```

- 步骤清单仅用于指导，**不要求每条步骤单独打卡**；一次“我完成啦”即可提交整个任务。
- 现实任务由儿童主动点击；如果家长审核，转到“已提交，等待爸爸妈妈确认”，不得提前加分。
- 自助确认任务则直接完成并发星星。防抖与状态验证要阻止重复提交。
- 已提交页面只允许查看状态，不允许重复提交；拒绝后回到“待完成”，可再次尝试。

### S03 — 赛车前进反馈（弹层）

流程为：**审核成功 → 完成印章（约 0.4s）→ 赛车沿赛道前进（约 1.2s）→ 星星入账提示（约 0.6s）**。展示“第 N 站完成啦”“获得 +X 星”“下一站”。

- 任务确认已经持久化成功后才播放动画；**不能以动画完成回调作为入账依据**。
- 多个审核结果待播放时，合并展示或依次展示，不能导致分值重复。
- 当前页关闭、刷新或动画中断，不影响业务状态；动画可以跳过。
- 当日全部有效站点完成时，用“冲线庆祝”替代普通反馈，显示完成数、当天星星总数和“去奖励仓库”。

### S04 — 奖励仓库（儿童）

顶部星星余额与“距离目标奖励还差 X 星”；以下分三栏：**赛车装扮 / 生活奖励 / 我的奖杯**。

- **赛车装扮：** 展示车漆、贴纸、轮毂，价格、是否已拥有、预览、兑换/装备；已拥有不能重复扣费。
- **生活奖励：** 奖励名称、星星价格、由家长定义的约定说明；点击“申请兑换”仅建立申请，批准后扣星并生成待兑现记录。
- **我的奖杯：** 里程碑只读展示，不允许消费性兑换；保留历史荣誉。
- 余额不足时禁用兑换但允许预览；奖励被停用后不得新兑换，已持有装扮和历史兑换记录保留。

### S05 — 我的赛车（儿童）

大赛车预览区 + 车身颜色选择 + 贴纸/轮毂选择 + 保存装扮。首发只实现**一个通用赛车车型**，更换颜色与贴纸；轮毂可作为次选功能。已解锁与未解锁清晰区分；未拥有只展示兑换入口，不能直接装备。建议使用分层 SVG/图片素材，不开发 3D 模型。

### S06 — 家长中心

顶部展示“今日已完成 / 待审核 / 近期兑换”；入口为“任务管理、待审核、奖励管理、成长记录”。支持一键添加任务模板。家长入口建议使用 PIN 或成人验证；**不能把前端 PIN 视为严格权限隔离**。儿童页面不出现删除、分值调整等管理控件。

### S07 — 任务编辑器（家长）

字段包括：任务名称（推荐不超过 12 字）、图标、类别、简要说明、可选 1–3 步指引、时段、重复规则（每天/星期/单次）、任务分值（0–3）、审核方式、是否启用、排序。保存前校验必填项。支持复制模板和停用模板。

修改周期任务只影响**尚未生成的未来日期**；如需同步修改今天，家长需显式选择“应用到今天”，不得静默篡改已完成历史。

### S08 — 家长审核与奖励管理

审核卡包括任务、孩子提交时间及“确认完成 / 再试一次”；审核通过会一次性完成任务、加星星、赛道前进；拒绝恢复待完成并保留审核记录。奖励管理包括现实奖励申请的批准/拒绝、批准后的待兑现记录、已兑现与取消退款；所有业务操作需留有可追溯事件 ID。

## 5. 关键业务规则（开发必须实现）

### 5.1 任务状态机

```text
pending（待完成） ──孩子提交──→ submitted（待审核）
      │                             │
      │（自助/系统确认）             ├──家长通过──→ completed
      └─────────────────────────────→ completed
                                    └──退回重做──→ pending

pending / submitted ──家长跳过──→ skipped
```

- 合法转换必须按状态校验；无效转换返回明确结果并保持原状态。
- 处于 `completed` 的任务再次 `approve` 必须是幂等空操作，不重复发星星。
- 家长对已完成任务的纠错属于单独的**管理调整事件**，首发可只提供“联系家长调整”而不开放任意撤销；不得让孩子通过撤销重复刷星。
- 跳过任务不发星星；默认不计入当日赛道有效站点数。若已完成任务不得直接跳过。

### 5.2 自然日、任务快照与赛道

- 采用设备本地 `YYYY-MM-DD` 日期作为每日任务分区键（与当前项目 `getTodayDateString()` 约定一致）。
- 任务模板与每日实例分别存储；每个实例保存名称、图标、分值、审核方式等**当日快照**。
- `ensureDailyTasks(date)` 可重复调用而不生成重复实例，稳定键建议 `date + definitionId + occurrenceKey`。
- 刷牙早晚各一次应建成两个不同模板或独立 `occurrenceKey`，不能因同一名称而冲突。
- 完成进度：`completed / 有效任务数`，有效任务不包括 `skipped`；无有效任务不触发冲线。
- 赛道完成顺序不强制。一天多次打开、跨午夜、时区变化、设备时钟异常需有防重记录。
- 历史记录保留，不因切换到第二天而被覆盖。

### 5.3 成长星星与幂等性

- 统一使用交易流水（正数获得，负数消费、正数退款），计算余额。
- 每次任务发星须绑定**唯一来源 ID**（例如 `earn:dailyTaskId`），从存储层约束不可重复入账。
- 每笔兑换绑定唯一兑换 ID；数字物品购买先校验是否已拥有、余额是否足够，再同一状态操作内完成扣费与物品归属。
- 现实奖励**申请不扣星**；家长批准时再次检查实时余额，然后扣星并标记 `approved`。申请时可显示“余额尚未锁定”。
- 取消已批准但未兑现的奖励时退款恰好一次；已兑现奖励默认不提供自动退款。
- 不允许负余额消费；补偿/调整必须记录操作原因及事件来源。
- **首发推荐一个独立的 `racing` Pinia 持久化 Store** 集中维护任务、审核结果、积分流水和兑换交易，避免多个 Store 分别写本地存储时发生跨 Store 半完成状态。外部页面只调用其业务 Action；业务规则拆到工具函数中。

### 5.4 反馈、行为习惯与儿童保护

- 取消“断签扣星”“排行榜竞争”等强刺激或惩罚机制；孩子当天未完成不产生负反馈。
- 任务动画播放时长短，支持跳过、静音和减少动态效果。
- 语音使用现有 `src/utils/speak.ts` 的能力并处理不支持/未授权情况，文字提示始终可见。
- 真实生活奖励由家长自定义，系统不承诺真实物品自动发放。
- 页面要支持大触控区域、高对比文本、不可只靠颜色表达状态。

## 6. 数据模型（建议 TypeScript 契约）

以下是建议的最小领域模型，开发可以在不改变行为含义的前提下细化字段。标识均使用稳定的 UUID 或等效唯一 ID，时间以毫秒时间戳存储。

```typescript
type TaskCategory = 'life' | 'learning' | 'exercise' | 'chores' | 'family';
type TimeSlot = 'morning' | 'afternoon' | 'evening' | 'anytime';
type CheckMode = 'parent' | 'self' | 'automatic';
type TaskStatus = 'pending' | 'submitted' | 'completed' | 'skipped';

type Schedule =
  | { kind: 'daily' }
  | { kind: 'weekly'; weekdays: number[] } // 0–6，星期日为 0
  | { kind: 'once'; date: string };        // YYYY-MM-DD

interface TaskDefinition {
  id: string;
  title: string;
  description?: string;
  steps?: string[];
  icon: string;
  category: TaskCategory;
  schedule: Schedule;
  timeSlot: TimeSlot;
  occurrenceKey: string;     // 用于同日多次：morning / evening 等
  points: number;            // 0–3
  checkMode: CheckMode;
  enabled: boolean;
  sortOrder: number;
  createdAt: number;
  updatedAt: number;
}

interface DailyTask {
  id: string;
  definitionId: string;
  occurrenceKey: string;
  date: string;
  title: string;             // 当日快照
  icon: string;
  description?: string;
  points: number;
  checkMode: CheckMode;
  timeSlot: TimeSlot;
  status: TaskStatus;
  submittedAt?: number;
  completedAt?: number;
  skippedAt?: number;
  approvedBy?: 'parent' | 'self' | 'system';
}

type PointType = 'earn' | 'redeem' | 'refund' | 'adjust';
interface PointTransaction {
  id: string;
  sourceId: string;          // 唯一业务来源；发星/消费/退款防重
  type: PointType;
  amount: number;            // 获得/退款为正，消费为负
  createdAt: number;
  note?: string;
}

interface RewardDefinition {
  id: string;
  title: string;
  icon: string;
  type: 'cosmetic' | 'real_world';
  cost: number;
  enabled: boolean;
  cosmeticSlot?: 'color' | 'sticker' | 'wheel';
  assetId?: string;
  description?: string;
}

interface Redemption {
  id: string;
  rewardId: string;
  rewardTitleSnapshot: string;
  costSnapshot: number;
  status: 'requested' | 'approved' | 'fulfilled' | 'rejected' | 'cancelled';
  requestedAt: number;
  approvedAt?: number;
  fulfilledAt?: number;
  cancelledAt?: number;
}

interface GarageState {
  ownedItemIds: string[];
  equipped: { colorId: string; stickerId?: string; wheelId?: string };
}

interface RacingState {
  schemaVersion: 1;
  taskDefinitions: TaskDefinition[];
  dailyTasks: DailyTask[];
  pointTransactions: PointTransaction[];
  rewards: RewardDefinition[];
  redemptions: Redemption[];
  garage: GarageState;
  playedFeedbackEventIds: string[];
  parentPreferences: { soundsEnabled: boolean; reduceMotion: boolean };
}
```

**示例：** 某天有 5 个有效任务，其中 2 个已完成、1 个待审核、2 个待完成；进度为 **2/5**，待审核不计入已完成。确认待审核任务后成为 **3/5**，同时产生 `earn:<dailyTaskId>` 流水且只出现一次。

## 7. 主要接口 / Store Action 约定

| Action / Selector | 输入 | 输出与主要约束 |
|---|---|---|
| `createTaskDefinition(input)` | 模板配置 | 校验周期和分值，生成稳定 ID |
| `updateTaskDefinition(id, patch)` | ID、修改项 | 默认仅影响未来未生成的每日实例 |
| `ensureDailyTasks(date)` | 本地日期 | 幂等生成当日任务，返回任务列表 |
| `submitTask(dailyTaskId)` | 当天任务 ID | `pending→submitted` 或自助完成；重复调用无副作用 |
| `approveTask(dailyTaskId)` | 已提交任务 ID | 完成任务 + 一次性入账 + 反馈事件 |
| `rejectTask(dailyTaskId)` | 已提交任务 ID | 返回待完成，保留审核事件 |
| `skipTask(dailyTaskId)` | 待完成或待审核任务 ID | 更新为跳过；不发星 |
| `requestRedemption(rewardId)` | 现实奖励 ID | 新建申请，不扣星 |
| `approveRedemption(id)` | 兑换申请 ID | 重新检查余额、扣星一次、状态变待兑现 |
| `redeemCosmetic(rewardId)` | 数字装扮 ID | 校验余额及归属，扣星并加入车库 |
| `equipCosmetic(itemId)` | 已拥有装扮 ID | 校验归属，仅更新当前装备 |
| `cancelRedemption(id)` | 已批准未兑现的申请 | 取消并退款恰好一次 |
| `markFulfilled(id)` | 已批准的现实兑换 | 标记已兑现，不再次扣星 |
| `getBalance()` | 无 | 流水求和；不可简单读 UI 缓存 |
| `getRaceProgress(date)` | 日期 | 返回有效站点数、完成数、是否冲线 |

所有状态改变应由业务 Action 统一实现，页面不得自行修改 `status`、余额或 `ownedItemIds`。在单设备本地持久化阶段，建议集中写入一份 versioned 状态快照，预留导出/导入及数据迁移接口；写入失败应提示并阻止显示虚假成功状态。

## 8. UI 视觉与动效交付规范

### 8.1 风格定位

**像一本会动的赛车绘本**：软萌小车、简化弯道、清晰的任务地标，延续 KidBridge 目前的糖果色、圆角卡片和轻快感，不做写实竞速或复杂 3D 游戏。

| Token | 建议值 | 用途 |
|---|---|---|
| Coral | `#FF6B6B` | 品牌主色、强调动作 |
| Orange | `#FF8C42` | 赛车、前进反馈 |
| Mint | `#3BBFB6` | 已完成、成功状态 |
| Sky | `#5BA8F5` | 辅助卡片、信息 |
| Gold | `#F5B417` | 星星、奖励、冲线 |
| Cream | `#FFF9E6` | 大面积背景 |
| 圆角 | 卡片 20–24px，大面板 28px | 与现有项目协调 |
| 点击区域 | 建议 ≥48×48 CSS px | 儿童触控友好 |

### 8.2 需要设计师交付的素材

1. 一套原创小赛车：基础车身、车漆颜色层、轮胎层、贴纸层；可优先 SVG 分层。
2. 赛道地图：起点、普通任务站点、待完成、已完成、终点、赛车行驶路径。
3. 图标：刷牙、阅读、玩具、运动、数学、英语、家务、亲子活动等。
4. 反馈素材：完成印章、星星飞入、赛车前进、冲线彩带、礼物解锁。
5. UI 设计稿：至少 S01、S02、S03、S04、S05、S06 的手机主态和关键状态；桌面响应布局。

### 8.3 状态与可访问性

- `pending`：浅暖底、清晰主按钮；`submitted`：等待确认，不再允许重复点击；`completed`：旗帜 + 勾号；`skipped`：中性、不施加负面颜色。
- 提示同时包含文字和图标；任务可选语音朗读，关闭声音时功能仍可用。
- 动画 2–3 秒，有跳过入口；尊重设备减少动态效果；禁止无限循环庆祝动效。
- 小屏不横向溢出；大屏限制内容宽度，不把任务卡扩张到难以阅读。

| `src/pages/math/challenge/index.vue` | **后续迭代**连接学习事件；首发保持原闯关功能不变 |

### 9.3 持久化与迁移

- 与旧学习状态 `kidbridge-app-storage` 分离，新建 `kidbridge-racing-storage-v1`，避免重置旧学习进度时误清新模块数据。
- 存储结构有 `schemaVersion`，启动时验证并迁移；遇到损坏数据要降级提示，不要静默丢失全部记录。
- 首发本地使用的限制须在家长设置中提示：跨设备不同步，清理浏览器数据可能丢失记录。
- 设计 JSON 导出/导入契约；首发至少提供可恢复的备份机制或将其列为上线前阻断项（避免持续积累的奖励突然丢失）。
- 本地无并发事务和安全身份认证保证；云同步上线前明确限制同设备使用，不声称可以远程审核。

### 9.4 后续学习联动预留

以后新增可信学习完成事件（包含 `eventId`, `module`, `completedAt`, `activity`），由赛车业务层判断是否匹配当日学习任务。**单道题答对不等于一次现实任务完成；自动打卡以完整学习单元/达成阈值为触发条件**，同一任务同一天最多奖励一次。

## 12. 项目执行建议与交付边界

### 12.1 建议实施顺序

1. **数据与规则先行：** 建立 `racing` 领域模型、任务生成、审核状态机、流水与积分不重复机制。
2. **完成可用闭环：** 家长创建任务 → 儿童打卡 → 家长确认 → 赛道前进 → 星星增加。
3. **加入奖励体验：** 奖励仓库、车库换装和现实奖励申请/兑现。
4. **高保真视觉与兼容性：** 用最终插画和动效替换线框展示，完成移动端/小程序验证。
5. **测试验收后合并上线：** 不在核心业务状态尚不稳定时只发布动画演示。

### 12.2 高保真 UI 尚需输出的内容

开发可先按本文件实施功能结构，但**不能把文字线框视为已定稿的像素级 UI**。正式设计仍需确定：赛车造型、地图节点位置、任务图标套件、奖励卡样式、品牌组件细节、响应式布局以及动画素材。此项属于视觉交付，不是需要重新讨论的产品功能缺口。

### 12.3 最终交付物

- 可运行的 KidBridge 赛车成长计划模块（H5，兼顾微信小程序）。
- 页面、组件、任务/奖励状态模型与持久化实现。
- 统一的美术资源及可关闭的短反馈动画。
- 单元测试、关键操作验收记录、兼容性测试说明。
- README / 项目文档更新：使用方法、家长管理、数据保存限制、部署方式。

### 12.4 开发者开工前需知

**已经确定：** 用户角色、儿童与家长端页面范围、主流程、奖励规则、状态机、技术栈、数据隔离和验收口径。
