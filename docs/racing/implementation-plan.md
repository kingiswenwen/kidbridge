## 领域契约补充

采用独立 `racing` Store 和 `kidbridge-racing-storage-v1`；任务模板、日期实例、审核事件、积分流水、兑换、车库在同一版本化快照中更新。

- `DailyTask` 增加 `steps`、`category` 等展示快照，避免改模板影响历史指导内容。
- 新增审计事件模型：稳定事件 ID、业务对象 ID、事件类型、原状态/新状态、发生时间、原因；记录提交、退回、审批、跳过及退款。每次重新提交用新的提交事件，完成奖励仍按实例唯一来源去重。
- `PointTransaction.sourceId` 唯一，例如 `earn:<taskId>`、`redeem:<redemptionId>`、`refund:<redemptionId>`。状态操作先校验当前状态和余额，不能只依赖按钮防抖。
- 现实奖励申请保存名称/价格快照；审批时按申请约定价格重新检查余额。编辑奖励不追溯更改现有申请；奖励停用不删除历史兑换。并发申请不预占余额，批准顺序以实时余额为准。
- 数字装扮兑换绑定物品与唯一购买来源；已有物品再次兑换为空操作或明确业务结果，不重复扣星。
- 余额从流水计算，不维护可被页面直接修改的余额字段；金额使用非负整数配置与带符号整数流水。

## 保存成功与多次操作

现有持久化插件的普通自动写入，不等同于可回滚事务。新业务采用统一的提交入口：从当前有效快照派生下一状态 → 校验状态转换与唯一来源 → 序列化并同步保存完整快照 → 保存成功后更新界面并发布反馈事件。写入抛错时保留旧状态，不显示完成动画、不假装已经入账。

H5 需要限制同时活跃的写入页：优先使用浏览器锁（能力检测），存储 revision 与写入前重读防陈旧；不支持锁的平台采用同设备单活跃会话约束与明确提示，不声称纯 localStorage 具有跨标签事务保证。小程序依照单实例生命周期恢复快照。首发不声称远程审核或防恶意篡改。

初始化应区分首次使用与损坏存储：先做结构/版本校验，保留损坏原始数据以供导出恢复，不把异常当作空数据覆盖。备份导入先整体校验再一次替换；拒绝不支持的版本、重复来源流水、非法装备和非法状态，失败不触碰当前数据。备份包含业务数据，不导出 PIN 等验证凭据。

## 日期与赛道边界

- 实例键绑定本地日期、模板 ID 和 occurrenceKey；重复进入、跨午夜、时钟回拨都不能重建相同实例。
- 模板编辑只作用未来未生成实例；显式应用今天仅变更允许修改的未完成项，保留完成历史。
- 跳过移出有效分母；0 项或全部跳过不触发冲线。0 星任务仍推进赛道。
- 不同日期的审核只更新对应日期的任务与历史；星星余额可增加，今天赛道不能因昨天任务获批而前进。
- 审批反馈与积分事务分离：状态保存后排队；按事件 ID 记录播放，动画跳过/中断/刷新不再次记账。
- 午夜后旧页面提交、历史任务补审、当天新增/跳过后的赛道比例变化需在领域测试中显式覆盖；不伪造设备时钟防作弊能力。
- 默认建议：允许家长补审已存在的历史提交，并在记录中保留原日期和实际审批时间；不自动把过期 pending 任务改为失败。

## 需要在正式实现前明确的配置

核心玩法不再重复确认。下列规则文档未完全指定，界面与工程稿中标为建议，不能当作已确认核心需求：默认装扮价格/奖杯条件、PIN 恢复方式、历史待完成任务能否补提交、同一生活奖励多笔未处理申请的限制、当天新增任务后冲线反馈的重放口径。建议奖杯只展示已达成的明确里程碑；不额外发积分；不通过删除数据恢复 PIN。
