# 赛车成长计划：页面与视觉规格

状态：本轮按用户继续完成全部功能的要求，采用绘本弯道方向实现。产品规则以 [V1.0](requirements-v1.0.md) 为准；本文件补充可评审的界面安排，不把设计图视为功能实现。

## 设计基础

- 用户：3–6 岁儿童；家长在同设备管理。手机基准 390×844 CSS px，同时覆盖 320px 窄屏。
- 表现：原创扁平绘本小赛车、简化弯道、易识别的任务图标；车型一款，车漆与贴纸分层，轮毂后续按首发范围决定。
- 颜色：Coral `#FF6B6B`、Orange `#FF8C42`、Mint `#3BBFB6`、Sky `#5BA8F5`、Gold `#F5B417`、Cream `#FFF9E6`。正文使用现有深色 `#1F2937`，辅助正文不能用低对比的浅灰。
- 字体：沿用应用 PingFang SC / Noto Sans CJK SC / Microsoft YaHei 系统字体栈。儿童页标题 24–28px，主要任务名 20px，正文 16–18px；不依赖儿童阅读长说明。
- 主操作高度至少 56px，其余可点击区域至少 48×48px；卡片圆角 20–24px，大面板 28px。
- 每屏只突出一个主动作；状态同时用图标与短文字表达，不仅依赖颜色。卡片仅在独立任务/奖励等对象上使用，不层层套卡片。
- 页面保留返回按钮，不增加第六个全局 Tab。家长入口从个人中心进入，儿童页不直接放管理、删除、调分按钮。

## 统一评审样例

日期若显示，为 2026-10-29，星期四。星星余额 18。

| 任务 | 时段 | 状态 | 进度计入 |
| --- | --- | --- | --- |
| 刷牙 | 早晨 | 已完成 | 是 |
| 整理玩具 | 随时 | 已完成 | 是 |
| 阅读绘本 | 随时 | 待完成 | 否 |
| 户外运动 | 下午 | 等家长确认 | 否 |
| 收拾餐具 | 晚上 | 待完成 | 否 |

赛道显示 **2/5**；18 星是历史流水余额，不表示今日所得。站点是完成数量的表达，不锁定任务执行顺序。

## S01 今日赛道

信息顺序：返回与标题 / 星星余额 → 简短问候与 2/5 进度 → 赛车与抽象站点 → 按时段组织的任务列表 → 我的赛车、奖励仓库两个入口。

三种候选仅比较布局：绘本弯道突出赛道；出发小站突出当前可行动任务；彩虹里程突出按时段排列的任务。布局必须保留其他任务可自由选择的入口，不能把“推荐下一项”变成强制顺序。

| 状态 | 文案与图标 | 可执行动作 |
| --- | --- | --- |
| 待完成 | 任务图标、去完成 | 打开详情 |
| 待审核 | 时钟、等家长确认 | 查看提交状态，无重复提交按钮 |
| 已完成 | 勾号与旗帜、已完成 | 查看详情与获得星星，不再次打卡 |
| 已跳过 | 中性横线、今天先休息 | 只读回看，不使用红色失败表现 |

0 项任务显示“今天是自由冒险日”，没有冲线、额外星星或催促；家长设置入口需要验证。全部跳过也没有有效赛道，不触发冲线。超过 8 项固定顶部进度、任务列表滚动，内容底部不被操作条遮挡。加载/存储失败不能显示虚假成功或擅自重置任务。

## S02 任务详情与打卡

顶部返回；大图标与任务名；一行说明和“听一听”；1–3 步可选指导；星星收益；底部大按钮“我完成啦”。指导步骤无需逐项打勾，不制造额外操作门槛。

家长审核任务提交后原位呈现“已经提交，等爸爸妈妈确认”，不增加余额、不播放完成动画。自助确认任务保存成功后进入 S03。连点时主按钮立即进入忙碌态，但最终仍由业务层检查状态与唯一事件。失败恢复可重试，并说明“还没有保存，再试一次”。拒绝后显示温和提示“再试一次吧”，恢复主按钮。

已完成、已跳过、历史待审核任务均提供明确只读/操作边界；家长审批入口不出现在儿童详情中。语音不支持时文字始终可见，不能仅用系统提示框代替步骤正文。

## S03 前进与冲线反馈

覆盖层而非新路由。先完成存储，再播放：完成印章约 0.4s → 赛车移动约 1.2s → 入账提示约 0.6s。显示“第 N 站完成啦”“获得 X 星”，0 星任务显示完成与进度，不制造 +0 奖励。可随时跳过。

减少动态效果时改为静态完成状态与短淡入；静音时不播放音效。刷新、离开、跳过动画不改变任何流水。批量审批按事件去重合并反馈，跨日期的审批反馈必须显示所属日期，不推动今天的赛车。没有审批结果时不循环播放庆祝。

冲线主态显示完成数、今日已获得星星以及“去奖励仓库”；不凭空赠送额外冲线积分。赛道/任务发生管理调整后，不重复发放或虚构奖励。

## S04 奖励仓库

顶部返回与余额；模块分栏“赛车装扮 / 生活奖励 / 我的奖杯”。第一屏控制物品数量，保证插画、价格、主动作清晰。

- 装扮：未拥有且余额足够为“兑换”；不足为“还差 X 星”并可预览；已拥有为“去装备”；已装备为“正在使用”。拥有状态不能再次扣星。
- 生活奖励：显示家长约定与价格，“申请兑换”后显示“等家长确认”，明确申请尚未扣星。批准后显示“等待兑现”，兑现后显示历史记录；拒绝无扣费，取消已批准未兑现项退款一次。
- 奖杯：只读里程碑，不展示购买按钮。奖杯触发条件、默认装扮价格采用待确认的配置表，不能由设计插画擅自引入新奖励规则。
- 奖励停用：不能新兑换；历史记录和已拥有物品保留。

目标奖励只在孩子/家长确实选定目标后展示“还差 X 星”，没有目标时不编造目标。

## S05 我的赛车

上半部大赛车预览，下半部分组选择车漆与贴纸；已拥有项可预览，明确勾选态，底部“保存装扮”。未解锁项显示锁与价格，进入仓库后兑换，不直接装备。

预览与已保存装备分离，离开未保存时提供保留/离开选择。默认赛车始终可用。素材使用本地分层资源，小程序不依赖浏览器 DOM、外网 SVG 注入或 3D 库。换装不消耗已经兑换的装扮。

## S06 家长中心与验证

首次设置验证方式，验证后展示今日完成/待审核/待兑现；按优先级先显示待处理事项，再放任务管理、奖励管理、成长记录、数据备份及设置入口。家长布局沿用同一配色，但降低插画密度，提高信息可读性。

PIN 仅防误触，页面文案不宣称安全认证。验证凭据不跟普通成长数据一起公开导出；离开家长区域或会话过期后重新验证。恢复 PIN 的方式须在首发方案中明确，不设置会误删学习数据的重置入口。儿童返回键直接退出验证，不暴露管理动作。

## S07 任务编辑器

分三组：做什么（名称、图标、分类、说明、1–3 步）；什么时候（时段、每天/选星期/单次日期）；如何确认（0–3 星、家长审核/自助确认、启用与排序）。首发不开放尚未接入的自动学习打卡选项。

模板是可编辑起点，不能添加后立即生成重复任务。编辑周期任务保存时默认只作用未来；“应用到今天”需明确选中，完成与已审核历史不被覆盖。字段错误贴近对应输入项说明，保留草稿。12 项上限在生成和编辑处都给出一致提示。

## S08 审核与奖励管理

任务审核项显示所属日期、任务名、提交时间，以及“确认完成 / 再试一次”。星星入账与审批结果作为一次业务操作提交；连点或返回再进入不重复审批。

现实奖励申请显示奖励名、申请时价格快照和当前可用余额；批准前重新校验余额。余额不足时保留申请，显示原因，不扣费。批准后的待兑现项提供“已兑现”和“取消并退星”，取消确认显示返还数量；已兑现项无自动退款按钮。

## 响应式与动效验收

- 320–430px：单列、允许文字换行、安全区底部留白，无横向滚动；图标和按钮不挤压任务标题。
- 768px 起：与现有应用一致限制内容宽度；儿童页仍保留清晰单列任务，桌面可采用赛道/任务两列但任务可达性一致。
- 1024px 起：最大内容宽度沿用应用 860px；家长表单按关联字段分组，不把儿童任务行横向拉满。
- H5 使用键盘焦点、可访问名称；小程序保留同等触控与状态信息。减少动态效果同时支持系统设置（H5）与应用设置。
- 设计确认范围必须包括待完成、待审核、已完成、跳过、空态、余额不足、存储失败和动画跳过；单张主态图不代表全部验收。
