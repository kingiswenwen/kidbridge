# 赛车成长计划：实现与交付说明

本轮实现覆盖 V1.0 的 P0、P1 范围。没有账号服务、云同步、多孩子、远程审核、支付、排行榜或学习自动打卡；这些是文档约定的后续范围。代码通过独立功能分支和 PR 交付，不自动合并或发布。

## 页面和使用流程

1. 原互动学习首页新增“今日赛道”，原数学、拼音、英语、闯关入口及五个 Tab 保留。
2. 第一次进入赛道是自由冒险日，不凭空赠送星星。家长从个人中心或赛道入口进入家长中心，设置 6 位 PIN，单独保存恢复码。
3. 家长从模板创建任务，也可以自定义名称、说明、步骤、图标、类别、时段、重复周期、0–3 星、审核方式、启用和排序。推荐 3–5 项，每天最多 12 项。
4. 孩子可自由选择任务、听指引、现实完成后点击“我完成啦”。家长审核任务只进入待确认；自助任务保存成功后才发星并推进赛道。
5. 家长确认、退回或跳过任务；成长记录可查看日期、提交、审批、兑换事件和流水。历史任务允许补审，儿童不补提交过去日期的任务。
6. 孩子在仓库兑换车漆、贴纸和轮毂，车库保存已拥有装扮。现实奖励由家长配置，申请不扣星；批准扣星、待兑现、兑现或取消退星形成完整记录。
7. 家长中心“设置与备份”可调整声音、减少动态效果、目标奖励、导出/复制备份、读取 JSON 或粘贴校验恢复。恢复前保留本机旧快照；原学习记录不参与替换。

## 已落实的规则

- 每日实例使用日期、模板 ID、occurrenceKey 的稳定键；生成可重复调用，早晚同名任务独立。按设备本地日期分区，不覆盖历史。
- 模板和每日快照分离，步骤也包含在快照中。编辑默认用于未来；显式应用今天只修改待完成项，已提交或结束的记录不能被覆盖。
- 完成比例只计算有效任务，跳过移出分母。0 星任务也推进；无有效任务不冲线。历史审批不推进今天赛道。
- 入账和退款均有唯一业务来源。余额从流水求和；购买、审批、退款与对应状态在同一快照内保存，按钮防抖不是唯一保障。
- 数字装扮不重复购买，未拥有不能装备。现实奖励同一项只允许一笔待审核/待兑现申请；拒绝或取消后可重新申请。申请时要求当前余额足够，但不预占；批准时再次核对余额。
- 已提交的奖励名称与价格使用快照，后续修改配置不改变约定。停用只阻止新兑换，已拥有物品和历史申请保留。
- 冲线不额外赠星；每天冲线庆祝至多记录一次。奖杯条件为第一次完成任务、完成一天有效赛道、累计十个任务；达成时间持久保存，后续加任务不收回奖杯。
- 新任务只在当天首次生成或家长明确应用/额外安排后出现，不伪造关闭应用期间的后台任务执行。

## 数据结构与存储

`src/types/racing.ts` 定义领域契约，`src/utils/racing/engine.ts` 提供纯事务和校验，`src/stores/racing.ts` 负责 uni-app 存储、平台写入互斥和家长会话。页面只调用 Action，不直接改任务状态、积分或归属。

| 键 | 内容 | 备份行为 |
| --- | --- | --- |
| `kidbridge-app-storage` | 原学习记录与设置 | 赛车模块不改此数据结构 |
| `kidbridge-racing-storage-v1` | schemaVersion、revision、模板、每日任务、流水、兑换、车库、审核事件、反馈与奖杯、偏好 | 成长 JSON 的主体 |
| `kidbridge-racing-parent-v1` | 加盐 PIN 摘要、恢复码摘要、错误次数、短暂锁定信息 | 不包含在成长备份中 |
| `kidbridge-racing-storage-v1:before-restore` | 恢复前的旧原始快照 | 恢复前先保留，可取回再次校验 |
| `kidbridge-racing-storage-v1:writer` | 旧 H5 引擎的短写入租约 | 临时协调，不导出 |

写入顺序为读取最新快照、校验和计算完整下一状态、同步写入、发布界面成功。存储异常不会发布完成反馈。现代 H5 使用 Web Locks 串行化多个页面的写入；旧引擎降级短租约并提示只保留一个页面，不能把 localStorage 宣称为数据库事务。首发按同设备使用，不提供跨设备安全或防篡改保证。

备份不超过 8MB；导入校验版本、ID 唯一性、任务快照、流水来源、余额、兑换关联、装备归属、审计及反馈。损坏数据不自动覆盖为空；家长可以导出原始数据再恢复。v1 支持奖杯字段的增量补齐，未知版本拒绝导入并保留现有数据；后续破坏性版本需另写迁移，不能静默丢失数据。

PIN 是防误触手段。家长会话在内存中保留至多十分钟，切回儿童功能、退出或应用进入后台后失效；每个管理 Action 再次检查会话。连续错误五次短暂锁定一分钟。首次恢复码仅展示一次，忘记 PIN 可通过恢复码重新设置，不删除成长或原学习数据。PIN 和恢复码都丢失时不提供清空用户数据的快捷恢复。

## 美术与响应式

沿用已有奶油底和糖果色，使用较深珊瑚色主按钮保证白字可读。`src/static/racing/` 是原创本地 SVG：四种车漆、可叠加贴纸、轮毂、绘本赛道和统一图标。没有引入 3D 或大型动效框架。

任务提交与审核状态使用图标加文字。动画与账务分离，可跳过、静音、减少动态效果；H5 同时尊重系统减少动态效果。手机单列、大屏限制宽度，奖励网格增加列数。H5 的自定义按钮提供角色、焦点和 Enter/Space 激活。

## 本地运行与验证

```bash
npm ci
npm run type-check
npm run test:racing
python3 -m unittest discover -s tests/deployment -v
npm run build:h5
npm run build:mp-weixin
# 首次运行浏览器测试时安装浏览器；若系统已有 Chromium，也可设置执行文件路径。
npx playwright install --with-deps chromium
npm run test:racing:e2e
```

浏览器测试默认使用系统 `/usr/bin/chromium`，否则使用 Playwright 浏览器；可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 显式指定。截图和结果写入被忽略的 `artifacts/racing-browser/`，CI 另外保存为构建产物。每次测试使用隔离浏览器上下文和本地静态服务器，不操作真实用户数据或生产站点。

实际结果和逐项验收见 [validation.md](validation.md)。微信构建成功不代表开发者工具或真机手测通过。

## 部署与回滚

H5 仍执行 `npm run build:h5`，将 `dist/build/h5/` 的完整内容按 [服务器部署文档](../server-cicd.md) 发布，保留资源导航首页与 `learning.html` 两个入口。当前 PR 工作流增加了领域测试、小程序构建和浏览器流程，不更改原生产部署条件。

交付时不推送 main，不执行部署脚本。只有用户审核后合并，仓库既有 main 工作流才会部署。上线前应先导出真实成长备份，并补齐下述平台手测。

回滚代码使用现有发布备份/回退流程。赛车存储与旧学习分离，旧代码会忽略新键；不通过删除本地数据回滚。再次升级后仍可读取 v1 快照；如发生数据恢复操作，可取回恢复前的本机快照。浏览器缓存、原有设置、源站发布文件保留策略遵循现有部署脚本。
